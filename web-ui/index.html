CosmoScan

Portal for submitting student works, technical checks and content visualization

Architecture API and Swagger Health Submit work Reports Word cloud JaCoCo

System diagram

CosmoScan is a set of microservices behind an API Gateway. The portal sends requests to the gateway; the services talk to each other inside the internal network.

API connection

The forms below send requests to the API Gateway (see the diagram above).

Single entry point. Defaults to port 8090. Change it only for a non-standard deployment.

API documentation (Swagger UI)

Interactive OpenAPI documentation of each microservice, proxied through the gateway.

submission-service POST /works - work submission Student submission scenario, WorkResponse model. file-storing-service POST/GET /files File upload and download (pdf, docx, txt, up to 1 MiB). analysis-service GET /works/{id}/reports, /word-cloud Technical reports and word cloud data.

Health check (Spring Actuator)

Direct links to /actuator/health of the gateway and the backend services.

gateway http://localhost:8090/actuator/health Opens in a new tab - Actuator JSON. submission-service http://localhost:8091/actuator/health Opens in a new tab - Actuator JSON. file-storing-service http://localhost:8092/actuator/health Opens in a new tab - Actuator JSON. analysis-service http://localhost:8093/actuator/health Opens in a new tab - Actuator JSON.

UC-1 Submit work

A student uploads a file and immediately gets the technical check result. Maps to POST /works.

Required text parameter studentFullName of the multipart request. Stored in the work metadata and passed to analysis-service.
Parameter file. Allowed formats: PDF, DOCX, TXT. Maximum size is 1 MiB. ZIP and other types are rejected with 400.
Sends the form to the gateway. On success (201) the response holds the work id, fileId and the technicalReport block (ACCEPTED or NEEDS_REVISION status and a list of remarks).
